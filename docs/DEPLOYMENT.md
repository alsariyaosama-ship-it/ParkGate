# دليل نشر وتهيئة منظومة ParkGate على الشبكة المحلية (LAN)

يوضح هذا الدليل الخطوات التفصيلية لنشر وتشغيل منظومة **ParkGate** على الشبكة المحلية لمنتزه العائلات الترفيهي، بدءاً من تثبيت وإعداد خادم قواعد البيانات SQL Server Express، مروراً بتهيئة الشبكة وجدار الحماية، وتطبيق حزم الترحيل (Migration Bundles)، وحتى تثبيت التطبيق على أجهزة الشبابيك وبدء التشغيل.

لوحة الويب السحابية لها دليل منفصل: `docs/DEPLOYMENT_WEB_CPANEL.md`.

---

## 1. متطلبات بيئة التشغيل

### 1.1 جهاز الخادم (Server PC)
- **نظام التشغيل:** Windows 10 Pro / Enterprise أو Windows 11 أو Windows Server 2019/2022 (x64).
- **المعالج:** رباعي النواة بسرعة 2.5 GHz فأعلى.
- **الذاكرة العشوائية (RAM):** 8 GB كحد أدنى (16 GB مفضل).
- **التخزين:** SSD بمساحة حرة 50 GB على الأقل.
- **الشبكة:** عنوان IP ثابت (Static IP) على الشبكة المحلية (مثال: `192.168.1.100`).
- **محرك قواعد البيانات:** Microsoft SQL Server Express 2022 (أو Standard).

### 1.2 أجهزة نقاط الدخول / الشبابيك (Desk PCs)
- **نظام التشغيل:** Windows 10/11 x64 (تحديث حديث).
- **الذاكرة (RAM):** 4 GB كحد أدنى.
- **الشاشة:** دقة عرض 1080p (1920×1080) كحد أدنى، مع دعم High DPI (100% أو 150%).
- **أجهزة الإدخال:** قارئ باركود/QR يعمل كـ Keyboard Wedge (محاكاة لوحة المفاتيح).
- **الاتصال:** كابل إيثرنت محلي متصل بنفس الشبكة المحلية للخادم (سرعة 1 Gbps).

## 2. تثبيت وتهيئة SQL Server Express 2022

### 2.1 التثبيت
1. قم بتنزيل **SQL Server 2022 Express** من موقع Microsoft الرسمي.
2. اختر التثبيت المخصص (**Custom**).
3. اسم المثيل الافتراضي أو المسمى: `SQLEXPRESS` (مثال: `SERVER-NAME\SQLEXPRESS`).
4. وضع المصادقة (**Authentication Mode**):
   - اختر **Mixed Mode (SQL Server authentication and Windows authentication)**.
   - عيّن كلمة مرور قوية لحساب المدير `sa` واحتفظ بها في مكان آمن.

### 2.2 تفعيل بروتوكول TCP/IP ومنفذ الشبكة
1. افتح **SQL Server Configuration Manager**.
2. انتقل إلى **SQL Server Network Configuration** ← **Protocols for SQLEXPRESS**.
3. انقر بزر الفأرة الأيمن على **TCP/IP** واختر **Enable**.
4. افتح خصائص **TCP/IP** وانتقل إلى تبويب **IP Addresses**:
   - توجه إلى القسم الأخير **IPAll**.
   - احذف أي قيمة في **TCP Dynamic Ports**.
   - اكتب المنفذ الثابت **1433** في خانة **TCP Port**.
   - اضغط **OK**.
5. انتقل إلى **SQL Server Services** وأعد تشغيل خدمة **SQL Server (SQLEXPRESS)**.
6. تأكد من تشغيل خدمة **SQL Server Browser** وضبط نوع بدئها إلى **Automatic**.

### 2.3 تهيئة جدار حماية Windows (Windows Defender Firewall)
على جهاز الخادم، افتح موجه الأوامر PowerShell كمسؤول (Run as Administrator) ونفّذ الأوامر التالية لفتح منافذ الاتصال:

```powershell
# فتح المنفذ 1433 لخدمة SQL Server
New-NetFirewallRule -DisplayName "ParkGate SQL Server (TCP 1433)" `
    -Direction Inbound -Protocol TCP -LocalPort 1433 `
    -Action Allow -Profile Private,Domain

# فتح المنفذ 1434 لخدمة SQL Browser
New-NetFirewallRule -DisplayName "ParkGate SQL Browser (UDP 1434)" `
    -Direction Inbound -Protocol UDP -LocalPort 1434 `
    -Action Allow -Profile Private,Domain
```

## 3. قاعدة البيانات وحساب الدخول (R6.5)

لا يُثبَّت SQL Server إلا على جهاز الخادم. أجهزة الشبابيك عليها برنامج ParkGate فقط، وتتصل بالخادم عبر الشبكة.

### 3.1 الحسابان
| الحساب | من يستخدمه | الصلاحيات |
|---|---|---|
| حساب Windows للمسؤول على الخادم | سكربت الإعداد فقط، عند التثبيت والترقية | ينشئ قاعدة البيانات ويعدّل بنيتها (الترحيلات) |
| `parkgate_app` (حساب SQL) | البرنامج على كل الشبابيك، والخادم، وخدمة المزامنة | قراءة وكتابة ونسخ احتياطي فقط (`db_datareader`، `db_datawriter`، `db_backupoperator`). لا يستطيع إنشاء الجداول ولا حذفها ولا تعديلها |

حساب واحد تشترك فيه الشبابيك كلها. أما من فعل ماذا فيُعرف من مستخدمي ParkGate وسجل التتبع، وليس من حساب SQL.

### 3.2 السكربت
ينفّذه المثبّت تلقائيًا في وضع الخادم، في نافذة ظاهرة. ويمكن تشغيله يدويًا كمسؤول:
```powershell
& "C:\Program Files\ParkGate\scripts\Setup-ProductionDatabase.ps1" -MigrationBundlePath "C:\Program Files\ParkGate\database\ParkGate.Migrations.exe"
```
ماذا يفعل:
1. يطبّق الترحيلات بحساب Windows للمسؤول.
2. يتأكد أن SQL Server يقبل حسابات SQL (Mixed Mode، القسم 2.1). إن لم يكن كذلك يتوقف ويشرح السبب.
3. ينشئ `parkgate_app` بكلمة مرور قوية يولّدها، ويعرضها **مرة واحدة** وينتظر الضغط على Enter. سجّلها في مكان آمن، لأنك ستحتاجها على كل شباك.
4. يحفظ الاتصال بهذا الحساب مشفرًا في `%ProgramData%\ParkGate\connection.dat` على الخادم.
5. يفتح المنفذين 1433 و1434 في جدار الحماية للشبكات الخاصة فقط، ويحذف قواعد الإصدار 1.0.0 المفتوحة لكل الشبكات.
6. ينبّه إذا كانت شبكة الخادم مصنفة «عامة» (Public)، أو إذا لم يكن SQL Server يستمع على المنفذ 1433.

تشغيل السكربت مرة ثانية، كما في الترقية، **لا يغيّر كلمة المرور** ولا يكتب فوق `connection.dat`.

### 3.3 تغيير كلمة المرور
إذا تسربت كلمة المرور أو نُسيت:
```powershell
& "C:\Program Files\ParkGate\scripts\Setup-ProductionDatabase.ps1" -MigrationBundlePath "C:\Program Files\ParkGate\database\ParkGate.Migrations.exe" -ResetAppPassword
```
يعرض السكربت كلمة المرور الجديدة ويحدّث اتصال الخادم. ثم أدخلها على كل شباك من شاشة الاتصال (القسم 5.3).

### 3.4 شبكة الخادم
في Workgroup يصنّف Windows الشبكة أحيانًا «عامة». حينها لا تصل الشبابيك إلى SQL Server. غيّرها إلى «خاصة» من: الإعدادات ← الشبكة ← خصائص الاتصال ← شبكة خاصة.

## 4. تطبيق ترحيلات قاعدة البيانات (Migration Bundle)

تعتمد المنظومة على الترحيل الذاتي المجمّع بدون الحاجة لتثبيت .NET SDK على جهاز الخادم:

### 4.1 إنشاء حزمة الترحيل (على جهاز التطوير)
تبني السكربتات حزمة جديدة في كل مرة، فلا تُستخدم حزمة قديمة تنقصها ترحيلات:
```powershell
.\scripts\build-installer.ps1      # dist\database\ParkGate.Migrations.exe داخل المثبّت
.\scripts\Build-Production.ps1     # artifacts\production\database\ParkGate.Migrations.exe وملف SQL
```
الأمر اليدوي المكافئ يحتاج `--startup-project src/ParkGate.Infrastructure`، لأن مشروع WinForms لا يصلح لأدوات EF.

### 4.2 تطبيق الحزمة على الخادم
سكربت الإعداد (القسم 3.2) يطبّق الحزمة تلقائيًا. لتطبيقها يدويًا، نفّذها على الخادم كمسؤول بحساب Windows:
```powershell
.\ParkGate.Migrations.exe --connection "Server=.\SQLEXPRESS;Database=ParkGate;Trusted_Connection=True;TrustServerCertificate=True"
```

سيقوم الملف بإنشاء كافة الجداول والقيود (Constraints) والفهارس وتعبئة البيانات الأولية (البذور Seed Data) تلقائياً.

## 5. نشر وتثبيت التطبيق على أجهزة الشبابيك (Desk Clients)

### 5.1 حزمة التطبيق (Self-Contained Executable)
يتم نشر التطبيق كحزمة قائمة بذاتها (Self-Contained) لا تتطلب تثبيت .NET 10 Runtime على أجهزة الشبابيك:
```powershell
dotnet publish src/ParkGate.WinForms/ParkGate.WinForms.csproj `
    -c Release `
    -r win-x64 `
    --self-contained true `
    -p:PublishSingleFile=false `
    -o dist/client
```

### 5.2 التثبيت على أجهزة المستخدمين
1. انسخ محتويات المجلد `dist/client` إلى المجلد التالي على جهاز الشباك:
   `C:\Program Files\ParkGate\`
2. أنشئ اختصاراً على سطح المكتب للملف التنفيذي:
   `C:\Program Files\ParkGate\ParkGate.WinForms.exe`
3. تأكد من منح مجلد بيانات البرنامج الصلاحيات اللازمة:
   `%ProgramData%\ParkGate\`

### 5.3 ضبط الاتصال الأولي (First Connection Setup)
عند أول تشغيل للبرنامج على جهاز الشباك:
1. ستظهر شاشة **إعدادات الاتصال بقاعدة البيانات** تلقائياً لعدم وجود اتصال محفوظ.
2. أدخل بيانات الخادم:
   - **الخادم (Server):** عنوان IP الخادم (مثال: `192.168.1.100\SQLEXPRESS` أو `192.168.1.100,1433`).
   - **قاعدة البيانات:** `ParkGate`.
   - **نوع المصادقة:** مصادقة SQL Server.
   - **المستخدم:** `parkgate_app`.
   - **كلمة المرور:** التي عرضها سكربت الإعداد على الخادم (القسم 3.2).
3. اضغط **اختبار الاتصال** للتأكد من نجاح الاتصال بالخادم عبر الشبكة المحلية.
4. اضغط **حفظ ومتابعة**.
5. يقوم البرنامج بتشفير بيانات الاتصال وتخزينها بأمان في `%ProgramData%\ParkGate\connection.dat` باستخدام تقنية **Windows DPAPI** بنطاق الجهاز (`DataProtectionScope.LocalMachine`)، بحيث لا تظهر كلمات المرور كنص مقروء في أي ملف نصي أو إعدادات مفتوحة.

## 6. معالج البدء الأول (First-Run Admin Setup)

عند الاتصال بقاعدة بيانات جديدة فارغة:
1. يكتشف البرنامج عدم وجود أي حساب مدير مسجل في جدول المستخدمين.
2. تفتح شاشة **تهيئة حساب مدير النظام الأول**:
   - اسم المستخدم: `admin` (أو أي اسم مرغوب).
   - الاسم الكامل: (مثال: مدير منظومة الدخول).
   - كلمة المرور وتأكيد كلمة المرور: (8 خانات على الأقل تحتوي حروفاً وأرقاماً).
3. بعد حفظ الحساب، يتم تسجيل الدخول تلقائياً إلى واجهة البرنامج الرئيسية.

## 7. فحص الجاهزية والتشغيل التجريبي

قبل بدء العمل الرسمي:
1. قم بالدخول بحساب المدير والتوجه إلى قائمة **الإدارة ← إعدادات النظام**:
   - اضبط اسم المنتزه، وفترة السماح (الساعات)، والحد الأقصى للمجموعة.
2. توجه إلى **الإدارة ← نقاط الدخول**:
   - تأكد من تسجيل الجهاز الحالي وتعيين اسم الشباك (مثال: "شباك الدخول 1").
3. توجه إلى **الإدارة ← المستخدمين**:
   - أنشئ حسابات موظفي الشبابيك برتبة **موظف شباك (Operator)** وحسابات المشرفين برتبة **مشرف (Supervisor)**.
4. أجرِ محاولة دخول تجريبية واختبر قارئ الباركود وسرعة الاستجابة على الشبكة.

## 8. نشر خدمة المزامنة السحابية (ParkGate SyncAgent)

تطبيق خدمة مستقل يعمل في الخلفية على جهاز السيرفر لنقل التغييرات المسجلة في جدول `SyncOutboxes` إلى السيرفر السحابي (Cloud API) بصمت وأمان:

### 8.1 الإعداد والتهيئة
1. يتواجد الملف التنفيذي `ParkGate.SyncAgent.exe` في مجلد التثبيت أو النشر.
2. يستخدم الووركر نفس إعدادات الاتصال المشفرة بتقنية DPAPI من `%ProgramData%\ParkGate\connection.dat` أو من ملف الإعدادات `appsettings.json`.
3. اضبط إعدادات السحابة في `appsettings.json` (أو `%ProgramData%\ParkGate\appsettings.local.json`)، دون المفتاح:
   ```json
   "SyncOptions": {
     "Enabled": true,
     "IntervalSeconds": 30,
     "BatchSize": 100,
     "MaxRetries": 10
   },
   "CloudApi": {
     "BaseUrl": "https://api.yourpark.ly/"
   }
   ```
4. خزّن مفتاح السحابة مشفرًا بتقنية DPAPI (R8.3). افتح PowerShell كمسؤول في مجلد الوكيل، ثم نفّذ:
   ```powershell
   .\ParkGate.SyncAgent.exe set-cloud-key
   ```
   يطلب الأمر المفتاح ولا يعرضه أثناء الكتابة. يُحفظ في `%ProgramData%\ParkGate\cloudkey.dat`، ولا يعمل إلا على هذا الجهاز.
   بعد الحفظ أعد تشغيل خدمة `ParkGate SyncAgent`. لحذف المفتاح نفّذ `.\ParkGate.SyncAgent.exe clear-cloud-key`.
   المفتاح المشفر له الأولوية. إذا بقي `CloudApi:ApiKey` في ملف JSON يعمل الوكيل، لكنه يكتب تحذيرًا في السجل. احذفه من الملف.
   قيمة المفتاح هي نفس قيمة `PARKGATE_API_KEY` في ملف `.env` على الاستضافة.
   ولّدها مرة واحدة على السيرفر بالأمر `php artisan parkgate:generate-key`.
   إذا كانت `PARKGATE_API_KEY` فارغة فالسحابة ترفض كل طلبات المزامنة.
   يجب أن يبدأ `BaseUrl` بـ `https://`. الوكيل يرفض أي عنوان آخر ولا يرسل شيئاً، إلا إذا ضبطت `AllowInsecureHttp` على `true` (للتطوير المحلي فقط).

### 8.2 التثبيت كخدمة ويندوز (Windows Service)
لتشغيل الووركر كخدمة تبدأ تلقائياً مع إقلاع السيرفر:
1. افتح PowerShell كمسؤول (Run as Administrator).
2. نفّذ أمر التثبيت:
   ```powershell
   .\scripts\install-sync-service.ps1
   ```
3. للتحقق من حالة الخدمة وسجلاتها:
   - افتح تطبيق الخدمات `services.msc` وتأكد من حالة `ParkGate Sync Agent` (Running).
   - توجد ملفات السجل الدوارة في: `%ProgramData%\ParkGate\logs\sync-agent-YYYYMMDD.txt`.

### 8.3 إيقاف أو إزالة الخدمة
لإزالة خدمة الويندوز عند الحاجة:
```powershell
.\scripts\uninstall-sync-service.ps1
```

## 9. النسخ الاحتياطي وحماية البيانات الشخصية

قاعدة البيانات في المنتزه هي النسخة الوحيدة من أرقام الهواتف والأرقام الوطنية، لأنها لا تُرسل إلى السحابة (ADR-021).
لا يدعم SQL Server Express تشفير النسخ الاحتياطية، لذلك يحتوي ملف `.bak` هذه البيانات دون تشفير.
لهذا السبب يجب حماية مجلد النسخ على السيرفر، وتشفير أي نسخة تخرج منه (R6.9).

### 9.1 النسخ الاحتياطي اليومي
السكربت `scripts/backup.ps1` يأخذ نسخة كاملة مع `CHECKSUM`، ثم يحذف النسخ الأقدم من مدة الاحتفاظ (14 يوماً افتراضياً).
في كل تشغيل يقصر السكربت صلاحيات المجلد على ثلاث جهات فقط:
- مجموعة Administrators.
- حساب SYSTEM.
- حساب خدمة SQL Server، مثل `NT Service\MSSQL$SQLEXPRESS`، لأنه هو من يكتب ملف النسخة.

أي مستخدم عادي على السيرفر لا يستطيع بعد ذلك فتح المجلد أو نسخ ملفاته.
لذلك يجب تشغيل السكربت كمسؤول، وإلا يتوقف برسالة واضحة.

جدولة التشغيل في Task Scheduler:
1. أنشئ مهمة جديدة تعمل باسم `SYSTEM`، وفعّل الخيار «Run with highest privileges».
2. البرنامج: `powershell.exe`
3. المعاملات:
   ```
   -ExecutionPolicy Bypass -NoProfile -File "C:\Program Files\ParkGate\scripts\backup.ps1" -ServerInstance "localhost\SQLEXPRESS"
   ```
4. التوقيت: يومياً الساعة 02:00 بعد إغلاق المنتزه.

إذا كان اسم حساب خدمة SQL Server مختلفاً، فمرّره بالمعامل `-SqlServiceAccount`.
تجد الاسم الصحيح في `services.msc` ضمن خصائص خدمة SQL Server، تبويب «Log On».

### 9.2 النسخة خارج الموقع (Off-site)
النسخة على نفس السيرفر لا تحمي من سرقة الجهاز أو تلف القرص، لذلك احتفظ بنسخة أسبوعية خارج المنتزه.
لا تنسخ ملف `.bak` كما هو إلى فلاش أو بريد أو خدمة سحابية، لأنه غير مشفر.
الطريقة الموصى بها:
1. أنشئ حاوية مشفرة بـ BitLocker To Go على فلاش مخصص، أو أرشيف 7-Zip بتشفير AES-256 مع خيار تشفير أسماء الملفات.
2. استعمل كلمة مرور طويلة يحتفظ بها المالك وحده، ولا تكتبها على الفلاش أو بجانبه.
3. انسخ أحدث ملف `.bak` إلى الحاوية، ثم افصل الفلاش واحفظه خارج المنتزه.
4. جرّب الاستعادة على جهاز تطوير مرة كل شهر، حتى تتأكد أن النسخة صالحة وأن كلمة المرور معروفة.

### 9.3 حجم قاعدة البيانات
حد SQL Server Express هو 10 GB لكل قاعدة بيانات.
الجداول `AuditLogs` و`CardScanLog` ومحاولات الدخول المرفوضة تكبر باستمرار، ولا يُحذف منها شيء دون موافقة المالك (R6.8).
بعد كل «نسخ احتياطي الآن» يعرض البرنامج حجم البيانات ونسبته من الحد، ويحذّر عند 70% (R6.8).
يمكنك أيضاً مراقبة حجم ملف النسخة في سجل السكربت: السطر «Backup successfully created. Size: … MB».

**سياسة الاحتفاظ (اعتمدها المالك في 2026-11-18، ولا يحذف البرنامج شيئاً حالياً):**
| الجدول | المدة المقترحة | السبب |
|---|---|---|
| `CardScanLog` | 12 شهراً | سجل تقني لمسح البطاقات، قيمته بعد سنة قليلة |
| محاولات الدخول المرفوضة في `EntryAttempts` | 24 شهراً | تفيد في مراجعة النزاعات، ولا تدخل في إحصاء الزوار |
| `AuditLogs` | 36 شهراً | سجل المسؤولية عن التعديلات والتجاوزات |
| الدخول المسموح والمتجاوز، والقسائم، والزبائن | لا تُحذف | بيانات العمل نفسها (BR-14) |

الحذف، إن اعتُمد، يكون بأمر إداري صريح بعد نسخة احتياطية، وليس تلقائياً.

## 10. الترقية من الإصدار 1.0.0 إلى 1.1.0

نفّذ الخطوات بالترتيب. الترقية تحتاج إيقاف العمل على الشبابيك لفترة قصيرة.

### 10.1 قبل الترقية
1. ابنِ الإصدار على جهاز التطوير:
   ```powershell
   .\scripts\build-installer.ps1
   ```
   الناتج `dist\installer\ParkGate_Setup_v1.1.0.exe`. البرنامج فيه مضمّن مع .NET 10.0.15، فلا تحتاج أجهزة الشبابيك تثبيت .NET.
2. أغلق البرنامج على كل الشبابيك.
3. على جهاز الخادم، افتح PowerShell كمسؤول، ثم خذ نسخة احتياطية:
   ```powershell
   & "C:\Program Files\ParkGate\scripts\backup.ps1"
   ```
   تأكد أن ملف `.bak` الجديد موجود قبل المتابعة.
4. أوقف خدمة المزامنة القديمة:
   ```powershell
   Stop-Service ParkGateSyncAgent
   ```

### 10.2 الخادم
1. شغّل `ParkGate_Setup_v1.1.0.exe` واختر وضع الخادم.
2. يطبّق المثبّت الترحيلات الجديدة بحزمة `database\ParkGate.Migrations.exe`، ثم يحفظ الاتصال في `connection.dat`.
   - من الترحيلات الجديدة: جداول بطاقات الدخول تحت EF، وتاريخ آخر هدية، وأيام دخول الجهات.
   - بيانات بطاقات الدخول القديمة كانت تجريبية، ولا تُنقل (ADR-025).
3. إذا أردت تطبيق الترحيلات يدويًا بدل المثبّت:
   ```powershell
   & "C:\Program Files\ParkGate\database\ParkGate.Migrations.exe" --connection "Server=.\SQLEXPRESS;Database=ParkGate;Trusted_Connection=True;TrustServerCertificate=True"
   ```
   الاتصال بحساب Windows للمسؤول، وهو حساب الترحيل (القسم 3.1).
4. في أول ترقية ينشئ المثبّت الحساب `parkgate_app` ويعرض كلمة مروره مرة واحدة (القسم 3.2). سجّلها، لأن الشبابيك تحتاجها في الخطوة 10.4.

### 10.3 خدمة المزامنة
1. أزل الخدمة القديمة:
   ```powershell
   & "C:\Program Files\ParkGate\scripts\uninstall-sync-service.ps1"
   ```
2. خزّن مفتاح السحابة مشفرًا (§8.1، الخطوة 4):
   ```powershell
   & "C:\Program Files\ParkGate\sync-agent\ParkGate.SyncAgent.exe" set-cloud-key
   ```
3. افتح `%ProgramData%\ParkGate\appsettings.local.json` واحذف منه `CloudApi:ApiKey` و`AesKey` إن وُجدا. تأكد أن `CloudApi:BaseUrl` يبدأ بـ `https://`.
4. ثبّت الخدمة الجديدة من مجلد التثبيت:
   ```powershell
   & "C:\Program Files\ParkGate\scripts\install-sync-service.ps1"
   ```
   يجد السكربت الوكيل في `C:\Program Files\ParkGate\sync-agent` تلقائيًا.

### 10.4 أجهزة الشبابيك
شغّل `ParkGate_Setup_v1.1.0.exe` على كل شباك واختر وضع الشباك.
ثم افتح البرنامج، وغيّر الاتصال إلى حساب SQL `parkgate_app` بكلمة المرور التي عرضها سكربت الخادم (القسم 5.3). بعد ذلك لا تحتاج الشبابيك حسابات Windows مطابقة للخادم.

### 10.5 لوحة الويب
- ابنِ الحزمة وانشرها حسب `docs/DEPLOYMENT_WEB_CPANEL.md` §6. اللوحة تحتاج الآن PHP 8.4.1 أو أحدث.
- إذا أُنشئت قاعدة السحابة قبل R2، فبنيتها قديمة. في هذه الحالة أعد إنشاءها، ثم أنشئ المستخدم من جديد، ودع الوكيل يعيد الإرسال.

### 10.6 بعد الترقية
1. افتح «الإعدادات ← التطبيقات» في Windows وتأكد أن إصدار ParkGate هو 1.1.0.
2. سجّل دخولًا، ثم سجّل دخول زائر تجريبي وألغه بـ F8.
3. افتح «الجهات» وحدد أيام دخول كل جهة. كل الجهات تبدأ بكل الأيام.
4. بعد دقيقة تأكد أن حالة المنتزه في لوحة الويب حديثة، وأن سجل الوكيل في `%ProgramData%\ParkGate\logs` لا يحذّر من مفتاح غير مشفّر.

### 10.7 إذا فشلت الترقية
1. أوقف خدمة المزامنة، ثم استرجع النسخة الاحتياطية من الخطوة 10.1 في SSMS («Restore Database»).
2. ثبّت مثبّت الإصدار 1.0.0 من جديد على الخادم والشبابيك.
