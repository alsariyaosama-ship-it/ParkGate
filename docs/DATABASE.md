# ParkGate — Database Design

SQL Server Express (2022 or later), database `ParkGate`, schema `dbo`. Managed by **EF Core migrations** (code-first). This document is the source of truth for the model; if code and this file disagree, stop and ask.

## 1. Conventions

| Convention | Rule |
|---|---|
| Table names | PascalCase plural (`Beneficiaries`) |
| Keys | `Id`. Sequential `uniqueidentifier` for high-volume/syncable tables (`Beneficiaries`, `EntryAttempts`, `AuditLogs` uses `bigint`), `int IDENTITY` for lookup/admin tables (ADR-008) |
| Time | `datetime2(3)`, UTC, column suffix `Utc`. Dates without time use `date` |
| Text | `nvarchar` everywhere (Arabic). No `nvarchar(max)` except JSON/details columns |
| Enums | Stored as `tinyint`; values listed below must never be renumbered |
| Concurrency | `RowVersion rowversion` on mutable tables (also used for future F3 sync) |
| Audit columns | `CreatedAtUtc`, `CreatedByUserId`, `UpdatedAtUtc`, `UpdatedByUserId` on mutable business tables, filled by a `SaveChangesInterceptor` |
| Deletes | No hard deletes on business data (BR-14) |
| Defaults | DB time defaults use `SYSUTCDATETIME()` |

## 2. Enums

```
BeneficiaryStatus : 1 Active, 2 Suspended, 3 Blocked
EntryResult       : 1 Allowed, 2 Denied, 3 Overridden
DenialReason      : 1 CooldownActive, 2 HolderSuspended, 3 HolderBlocked,
                    4 CardExpired, 5 OrganizationInactive
                    (group size over the limit is a validation error, not a denial)
EntryChannel      : 1 Desk, 2 QrDesk (F1), 3 Gate (F2)
UserRole          : 1 Operator, 2 Supervisor, 3 Admin
WorkstationType   : 1 Desk, 2 Gate (F2)
```

## 4. Atomic check-in (BR-12, ADR-005)

All steps run in **one transaction** inside a single unit of work:

```sql
BEGIN TRANSACTION;  -- READ COMMITTED

-- 1) lock the holder row; a second desk blocks here until we commit
SELECT b.Id, b.Status, b.CardExpiryDate, b.LastGrantedEntryUtc, b.OrganizationId,
       o.IsActive AS OrgActive, o.CooldownMinutes
FROM dbo.Beneficiaries b WITH (UPDLOCK, ROWLOCK)
JOIN dbo.Organizations o ON o.Id = b.OrganizationId
WHERE b.Id = @BeneficiaryId;

-- 2) authoritative time
SELECT SYSUTCDATETIME();

-- 3) C#: Domain policy evaluates → EligibilityDecision (no SQL here)

-- 4) insert attempt (+ companions); if granted:
UPDATE dbo.Beneficiaries SET LastGrantedEntryUtc = @NowUtc WHERE Id = @BeneficiaryId;

COMMIT;
```

EF Core shape (Infrastructure):
- `IBeneficiaryRepository.GetForUpdateAsync(id)` → `FromSqlInterpolated($"SELECT * FROM dbo.Beneficiaries WITH (UPDLOCK, ROWLOCK) WHERE Id = {id}")`.
- `IUnitOfWork.GetDbUtcNowAsync()` → `SELECT SYSUTCDATETIME()`.
- The policy itself lives in Domain and is unit-tested without a database.
- Integration test (required): two parallel check-ins for the same holder → exactly one `Allowed`, one `Denied/CooldownActive`.

**Void recalculation (BR-13):** in one transaction, lock the holder row, mark the attempt voided, then set `LastGrantedEntryUtc = MAX(AttemptedAtUtc)` over that holder's non-voided `Allowed/Overridden` attempts (NULL if none).

## 6. Seed data (InitialCreate migration)

- Organization: `SSF` — «صندوق التضامن الاجتماعي», `IsDefault = 1`, `IsActive = 1`, `CooldownMinutes = NULL`.
- Age categories: «بالغ» («13 سنة فأكثر», 1) · «طفل» («من 3 إلى 12 سنة», 2) · «رضيع» («أقل من 3 سنوات», 3). Age ranges are display text only (editable).
- All settings in §5.
- **No users** — first-run wizard creates the Admin (ADR-012).

## 7. SQL Server Express on the LAN (summary — full guide in Phase 8 `docs/DEPLOYMENT.md`)
- Named instance `SQLEXPRESS` on the server PC; enable TCP/IP; fixed port (e.g. 1433) recommended; open the port in Windows Firewall.
- SQL authentication (workgroup networks rarely have a domain). App login `parkgate_app` mapped to the database with `db_datareader`, `db_datawriter` and `EXECUTE` only — not `db_owner`. Migrations run with a separate admin login.
- SQL Express has no SQL Agent → backups via `scripts/backup.ps1` + Windows Task Scheduler (Phase 8).
